# Optional capture service

This small Node function is a candidate for fetching public share pages outside Cloudflare's Worker network. The AIRef website, review, publication, records, and D1 storage stay on Cloudflare. The service has no storage or publication endpoint.

Cloudflare's normal fetch and its Free browser-fetch service both received an OpenAI block page for the reported ChatGPT link. On 4 November 2026, the authenticated Netlify draft and stable service both retrieved its two-message transcript, and the normal AIRef preview and production import APIs succeeded through this connection. Automatic Claude retrieval still failed; the browser helper remains its fallback. These results cover the tested links and current provider responses, rather than guaranteeing every future public share.

## Deployment conditions

Use a confirmed Netlify Free account with hard quota stops, or existing included Pro credits only with explicit operator authorization and verified disabled auto recharge. Do not upgrade a plan, enable paid add-ons, auto recharge, or paid overages. Check the actual account's plan and quotas rather than assuming that an existing website means its account is Free. Deploy as a separate project; do not replace the user's existing website or change DNS. Included credits share the existing team's quota; exhausting it can pause the team's projects.

On 4 November 2026, the official CLI approval succeeded, but the authenticated API reported the existing account as credit-based **Pro**, with auto recharge disabled. Deployment was initially held. The user subsequently explicitly authorized using existing Pro credits with no extra spend. A fresh authenticated account check confirmed auto recharge was still disabled before creating the separate capture-only project. No subscription, billing setting, member seat, paid add-on, DNS record, or existing site was changed.

The repository's root `package.json` supplies the dependencies. The root `netlify.toml` points only to the capture service's static placeholder and single function; the AIRef website continues to use Cloudflare's configuration. The function uses Netlify's standard Request/Response Functions API and the esbuild bundler. Run the Netlify CLI from the repository root; CLI 27 does not accept a `--config` argument. An offline package check is `npm exec --yes --package=netlify-cli@27.16.2 -- netlify build --offline --context deploy-preview`.

1. Authenticate the official Netlify CLI and inspect the intended account and plan.
2. Create a separate capture project under the verified account, without Git integration or DNS changes. Set a newly generated secret of at least 32 characters in its function environment as `AIREF_RELAY_SECRET`; keep it out of command arguments, chat, source, and logs. The CLI can import a private ignored environment file (capture its output privately, because it prints imported values), then `env:set AIREF_RELAY_SECRET --secret --scope functions --force --site <site-id>` converts it to a function-only secret without putting its value in command arguments.
3. Build and deploy a draft. POST the reported share URL to `https://<draft-host>/.netlify/functions/capture` with JSON `{ "url": "https://chatgpt.com/share/…" }` and the secret in the Bearer authorization header. Verify a 200 response, matching `X-AIRef-Source`, the correct transcript, and refusals for missing authorization and private URLs.
4. Only if the hosted test succeeds, configure the Cloudflare **preview** with `CAPTURE_RELAY_URL` and the matching secret as `CAPTURE_RELAY_SECRET`. Test the normal AIRef import and review flow there before setting these variables in production.

The integration is wired into `server/app.ts` and remains disabled without `CAPTURE_RELAY_URL`. Direct retrieval is attempted first. Only its explicit browser-capture-required failure can trigger the optional service; invalid URLs and oversized sources do not trigger it. Both variables are configured in preview and production, using the stable `https://airef-capture-ojwatson.netlify.app/.netlify/functions/capture` endpoint. The URL is a public operator setting; the shared secret remains in the two hosts' secret environments. The deployment script carries the URL into Wrangler's binding configuration while retaining existing secrets.

## Boundaries and validation

Rates checked on 5 November 2026: Netlify Free includes 300 credits per month with a hard limit and no auto recharge. Personal includes 1,000 and Pro starts at 3,000. The same usage rates apply: 10 credits/GB-hour of function compute, 20 credits/GB of outbound bandwidth, 2 credits/10,000 web requests, and 15 credits per successful production deployment. Deploy previews and branch deployments do not have the production-deploy charge, but their requests/compute/bandwidth still consume credits. See [current pricing](https://www.netlify.com/pricing/) and [credit accounting](https://docs.netlify.com/manage/accounts-and-billing/billing/billing-for-credit-based-plans/how-credits-work/). The credit allowance is shared across the team's projects. A hypothetical 1 GB allocation for 3 seconds plus a 0.6–0.75 MB response uses approximately 0.021–0.024 credits per capture; actual billing depends on measured function time and transferred bytes. This estimate is not a measured monthly bill or an availability guarantee.

The function accepts an authenticated POST containing one public ChatGPT or Claude share URL. It rejects private chats, arbitrary hosts, redirects, cookies, extra fields, and request bodies over 2,000 bytes. Its upstream fetch has a 15-second deadline and a 4 MiB streamed-source limit. It returns inert text with `Cache-Control: no-store`. Provider credentials and AIRef invitation codes are never forwarded. Publication still requires the existing review and confirmation step.

`tests/capture-relay.test.ts` checks both sides of this connection. `tests/import-api.test.ts` checks that a blocked direct import can use the service and retain the receipt/review/publication contract. Hosted compatibility was separately checked against the actual Netlify function, then the preview and production AIRef APIs. Missing authorization returned 404 at the capture service and 401 at AIRef; private-chat URLs returned 400. The production source digest and receipt were checked, and its actual response passed through the real frontend's review flow in an emulated DOM. Chrome control was unavailable, so this does not establish an interactive browser trial. No real transcript was published by these checks.
